The Package Manager

Weld

A sandboxed transactional package manager built for Arvor.

Sandbox Verification

Every transaction is first applied inside an LVM snapshot mounted at /nsm/weld/root. The sandbox runs under a strict SECCOMP filter, reduced Linux capabilities, and isolated mount namespaces via pivot_root. Only after a clean verification does Weld commit changes to your live system.

Signed Weld Repositories

Weld repositories are never trusted by default. Every repository metadata document must be accompanied by a minisign signature (Ed25519, optionally BLAKE2b-512 pre-hashed) and verified against the trusted keyring at /etc/weld/trusted_keys.

Transaction Snapshots

Before any install, upgrade, remove, or dist-upgrade, Weld asks NSM to capture a pre-transaction snapshot. If the host transaction fails, Weld automatically rolls the system back to that snapshot.

The Snapshot Engine

NSM

A tiny, dependency-light C tool that drives LVM Thin snapshots.

Thin Provisioning First

NSM detects whether the origin LV is a thin volume automatically. Thin snapshots are created instantly at near-zero cost. For legacy thick volumes, NSM sizes the snapshot intelligently (1G / 1.5G / 3G / 5G) based on free VG space.

Atomic Rollbacks

Rolling back the root filesystem schedules an lvconvert --merge and asks for a reboot.

Automatic Retention

Every apt or daemon-triggered snapshot triggers automatic cleanup, which keeps the 6 newest snapshots per category. If the thin pool crosses 93% usage, NSM deletes the largest snapshots first until the pool is back under threshold.

Help Center

Frequently Asked Questions

Why use LVM Thin with XFS or EXT4 instead of BTRFS?

XFS and EXT4 are high-performance, battle-tested journaling filesystems that offer extreme stability. Combined with LVM Thin snapshots, Arvor achieves atomic-like rollbacks without the metadata corruption risks sometimes associated with copy-on-write filesystems. XFS is mounted with nouuid on snapshot mounts, while EXT4 simply mounts the LV directly.

How do rollbacks actually work?

NSM integrates directly with LVM. Before any update, Weld asks NSM to capture a thin snapshot. If your system fails to boot, you simply select the previous snapshot to instantly revert all changes via an LVM merge.

Is the root partition strictly read-only?

No! That is the core philosophy of Arvor. We provide the safety nets of an atomic distribution (atomic rollbacks via NSM and transaction verification via Weld) while allowing you full write access to your filesystem when you need it.

What happens if the thin pool fills up?

NSM continuously monitors thin pool usage. If the pool crosses 93%, NSM automatically deletes the largest snapshots (manual, then auto, then daemon) until usage drops below threshold.

Does Weld verify packages before installing?

Yes. Weld verifies the SHA256 checksum of every downloaded package against the value declared in the repository metadata, and that metadata itself is signed with minisign / Ed25519. Repository metadata is never trusted without a valid signature.
